Kita Paham AI Academy, a Learning Management System for AI Literacy

A working Moodle 5.3 site that I set up, configured and run on my own server: three short modules on AI literacy, three roles with their own view, completion tracking, open badges, and a learning analytics page that shows lecturers where learners stop and which quiz questions trip them up.

How to try it

About ten minutes. Demo accounts are shared and reset every night at 03:00, so nothing you do there can break the site.

  1. Open the login page and answer “Who are you?” with Student, Lecturer or Admin. Each choice explains what that role does and logs you in with one click.
  2. As a student, continue with Module 1: read the first chapter, then take its quiz. Every answer gets feedback straight away; with 60 % the next chapter opens.
  3. Look at your progress on the home page: a bar per module, the next step, and the four badges you can earn, greyed out until you earn them.
  4. Log in again as a lecturer and open Learning insights: the learning path with its biggest drop, the questions marked for review, and the learners who may need a message.
  5. Log in as an admin to see the site at a glance and the places an operator needs most: users, courses, logs and permissions.

Three roles, three views

Each role is a standard Moodle role, so the permissions are Moodle’s own. After login the home page changes to what that person needs first.

Student

Moodle role: student

Sees

  • Progress per module and the next step to take
  • Chapters that open one after the other
  • Earned and open badges

Can

  • Read, take quizzes as often as needed, do the practice tasks
  • Enrol in a module by themselves
  • Download an earned badge as an Open Badge

Lecturer

Moodle role: editing teacher in every module

Sees

  • Per module: learners, finished attempts, average grade, unanswered questions
  • Learning insights for each module

Can

  • Answer questions in the module forum
  • Check grades and learner progress
  • Edit chapters, quizzes and settings

Admin

Moodle role: manager for the whole site

Sees

  • User accounts, active users, modules and completions
  • Learning insights for every module

Can

  • Manage users, enrolments, courses and categories
  • Read the logs and check permissions
  • Issue and review badges

The three public demo accounts carry an extra restriction role: they cannot change their password or profile, post in forums, send messages, assign roles or delete courses, so a shared account cannot be taken over or misused.

Learning insights

A small Moodle plugin I wrote for lecturers and admins. Moodle already stores every page view, attempt and completion; the plugin turns them into four answers for one module at a time.

Where do learners stop?
Share of enrolled learners at every step, chapter by chapter, with the biggest drop called out.
Which questions need another look?
First-try results per question and the wrong answer chosen most often. Below 50 % a question is marked for review: the question, its answers or the text may be unclear.
Who may need a message?
Learners who have not finished and have been quiet for a week, with where they stopped, such as “did not pass the quiz of chapter 2”.
How active is the module?
Learners active per day over six weeks, with a tooltip on every day and the same numbers as a table.

About the data. A public demo has almost no real learners, so the site includes a sample cohort of 60 simulated learners, labelled as such on the page. Their activity is produced with Moodle’s own functions (page views, quiz attempts with answers, completion), dated across six weeks and moved forward every night, so the Moodle reports and the badges show the same numbers as the insights.

How the site is run

The parts an operator deals with every day, set up so that changes are repeatable and tested.

Content as files

Chapters, quizzes and module settings live in HTML and JSON files. One script rebuilds a module in Moodle from them, with sections, access rules, completion criteria and enrolment, so a correction never depends on clicking through forms.

Nightly reset

Every night the database and files return to a saved snapshot, the sample cohort is moved forward to today and the caches are purged. The demo stays clean for the next visitor.

Quality checks

Browser tests log in with every role and check the dashboards, the quiz flow (passing opens the next chapter), the insights page, phone width, dark mode and horizontal overflow, with screenshots to review.

Accessibility and languages

Keyboard focus is visible, charts have a table view, status is never shown by colour alone, and the interface switches between English and German.

Hosting and security

Moodle, PostgreSQL and the web server run in Docker with automatic HTTPS, read-only containers, a database without internet access and a firewall that only opens the web ports.

Own theme

A child theme of Moodle’s Boost with its own front page, login with the role choice, role views and a portfolio banner on every page.
